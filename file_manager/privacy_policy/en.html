2. Data Handling Architecture & Local Storage Policy

File Manager is primarily designed as an offline-first tool dedicated to local storage management, file browsing, archivity, media playback, document editing, and biometric file security. The core features of the Application operate locally on your client device.

  • Local File Data: All file indexing, directory metadata creation, thumbnail generation, media rendering, archive manipulation (ZIP, TAR, RAR, 7Z), and code editing occur locally on your device. We do not transfer, mirror, or back up your personal files, photos, videos, audio, or documents to external cloud servers operated by us.
  • Biometric Credentials & Encryption: Secure folder authentication relies on Android System Biometric APIs (BiometricPrompt / FingerprintManager) and local cryptographic primitives. Your biometric data (fingerprints, facial metrics) is processed exclusively by your device's Secure Enclave / Trusted Execution Environment (TEE). We never access, store, or transmit your biometric identifiers.
  • App Database: Local app state, tags, custom categorization, favorites, and settings are stored locally in a sandboxed SQLite database via SQLite3 / Drift engine on your device.

3. Device Permissions & Purpose Breakdown

To provide full file navigation and execution functionality, the Application requests runtime and system permissions. Below is a detailed account of how each permission is utilized:

  • MANAGE_EXTERNAL_STORAGE / READ_EXTERNAL_STORAGE / WRITE_EXTERNAL_STORAGE: Granted to allow full file operations across shared device storage, including creating, renaming, deleting, copying, moving, archiving, and editing documents and media files.
  • READ_MEDIA_IMAGES / READ_MEDIA_VIDEO / READ_MEDIA_AUDIO: Required on Android 13+ to filter, organize, render thumbnails, and play media files stored on your local device storage.
  • CAMERA: Utilized solely if you use the document scanner or built-in camera capture features within the Application to capture photos directly into specific target folders.
  • USE_BIOMETRIC / USE_FINGERPRINT: Required to authenticate user identity before unlocking protected or hidden folders within the Application.
  • QUERY_ALL_PACKAGES / REQUEST_DELETE_PACKAGES / PACKAGE_USAGE_STATS: Used for app manager utilities, allowing you to view installed application storage usage, back up APK files, or trigger package uninstallation upon explicit request.
  • ACCESS_FINE_LOCATION / ACCESS_COARSE_LOCATION / NEARBY_WIFI_DEVICES / ACCESS_WIFI_STATE / CHANGE_WIFI_STATE / CHANGE_NETWORK_STATE: Requested exclusively to enable high-speed direct peer-to-peer (P2P) file transfers over Wi-Fi Direct or local Wi-Fi Hotspot networks. Location services are required by the Android operating system to scan for nearby Wi-Fi devices. Location data is never recorded, stored, or transmitted to any server.
  • POST_NOTIFICATIONS / FOREGROUND_SERVICE: Used to display persistent status updates during background operations, such as ongoing file transfers, batch compression/extraction, or storage cleanup tasks.

5. User Data Protection & Global Regulatory Rights

Depending on your jurisdiction, you possess specific statutory rights regarding your personal information under applicable global privacy laws, including the European Union General Data Protection Regulation (GDPR), the California Consumer Privacy Act (CCPA/CPRA), the Brazilian General Data Protection Law (LGPD), and the Indian Digital Personal Data Protection Act (DPDP):

  • Right of Access & Control: Because your file data remains exclusively on your local device, you maintain 100% control over your data. You can inspect, modify, export, or delete any file at any time directly through the Application or system file browser.
  • Right to Opt-Out of Personalized Ads: You can reset or disable your Advertising ID at any time via your device settings (Go to Settings > Google > Ads > Delete Advertising ID or Opt out of Ads Personalization).
  • Data Retention & Deletion: Uninstalling the Application permanently removes all sandboxed local database records, app caches, and stored configuration settings from your device. Files created in general shared storage remain under user control.
